# 17. REST API and API keys

Status: Accepted

## Context

`openticker-serve` (ADR 12) needs an HTTP surface: for scripts and tools that aren't MCP clients, for the alert webhooks and hosted strategy scripts to come, and for a web UI later. Anything that places orders on a network port needs authentication, even on localhost: any local process, or a browser page making requests to `127.0.0.1`, can reach it.

## Decision

- **The REST API mirrors the MCP tools one to one**, under `/api/v1`, returning the same result models (ADR 8). Each route is a thin call into the same use case the tool calls. A test fails if a tool has no route.
- **Routes are plain `def`**, run on FastAPI's thread pool, so use cases stay sync (ADR 2).
- **Every route except `/health` needs an API key** in the `X-API-Key` header. A missing, wrong or revoked key gets 401.
- **Keys are 32 random bytes with an `otk_` prefix, shown once at creation. Only their SHA-256 is stored.** A slow password hash (bcrypt, argon2) protects low-entropy passwords from guessing; a random 256-bit key can't be guessed from its hash, so a slow hash would only slow every request.
- **Keys are managed from the command line, not through MCP or REST**: `openticker-serve keys create <name>`, `keys list`, `keys revoke <name>`. A tool that returned a key would put it in the agent's context and transcript.
- **Key names are never reused**, even after a key is revoked. Orders placed over REST record `triggered_by="rest:<name>"`, so the audit log says which key placed them, and a name always means one key.
- **Each key has a scope.** Every key is `full` for now; narrower scopes arrive with Python script hosting (ADR 15). The column exists from the start because there are no schema migrations yet.
- **Errors map to statuses, with the same message the agent would see** (ADR 7): an unknown instrument, broker or underlying is 404, a broker failure (including an expired session) is 502, missing configuration is 503, and a malformed request is 422. A rejected order is not an error: it returns 200 with `status` and `reason`, like the tool.
- **The server binds to `127.0.0.1:8750`** unless `OPENTICKER_BIND` says otherwise, and warns at startup when bound beyond loopback or when no key exists yet.

## Consequences

- The MCP server and the REST API can run at the same time against the same sandbox; fills from both go through the same `BEGIN IMMEDIATE` transaction (ADR 11).
- `/docs` and `/openapi.json` are served without a key. They describe the API, not your data.
- Keys are sent in plain HTTP. That is fine on loopback; anything exposed beyond it needs TLS in front (a reverse proxy or tunnel).
