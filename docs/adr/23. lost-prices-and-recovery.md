# 23. Lost prices and recovery for strategy runs

Status: Accepted

## Context

ADR 13 set the model for lost prices: per instrument `live`, then `polling` after 10 seconds without a streamed price, then `stale` after 60 seconds without any price, and a stale leg stops its run with reason `tick_stale`. ADR 14 set the recovery rule: every order is recorded before it is sent, and on start an order recorded without an answer is reconciled against the sandbox before the run carries on, or the run stops with reason `recovery_failed`. The runner (ADR 21) had neither. A leg the feed went quiet on held up the strategy-wide rules forever, and a daemon that died between the sandbox filling an order and the run recording it lost track of that fill.

## Decision

We follow openalgo's tick feed and boot recovery, re-derived:

- **A price's age counts from the latest of the leg's entry, today's session open and the daemon's start, and only while its market is in session.** A positional run is not stale overnight or over a weekend, a leg held from yesterday has from the open to get its first price, and after a restart every leg gets a full window before it can go stale.
- **Polling.** Each second the strategy loop lists the contracts open runs hold. Every 2 seconds it fetches quotes, one batch per broker, for those with no streamed price for `STRATEGY_TICK_FALLBACK_SECONDS` (default 10). Polled prices go into the same latest-price cache as streamed ones. They never replace a newer streamed price, and they don't count as streamed, so a leg stays on quotes until the feed prices it again. A quote counts even for a contract that hasn't traded, so an illiquid leg is not stale while quotes answer.
- **Rate limits.** A broker that answers "too many requests" (`BrokerRateLimitError`, Kite's HTTP 429) is left alone for 2, 5, 10, then 30 seconds, longer each time in a row. Its legs keep ageing towards stale meanwhile. Any other failure, a network error included, is logged and tried again at the next poll: a poll never stops the runs being judged.
- **Stale stops the run.** When any leg the run holds, including one whose exit is being retried, has had no price from either source for `STRATEGY_TICK_STALE_SECONDS` (default 60), the run stops with reason `tick_stale`, every leg gets an exit, and the stop is notified like any other. It never resumes on its own; `start_strategy` starts a new run.
- **Stale exits are retried, not left resting.** ADR 13 had the close orders rest in the sandbox until a fresh price arrived. The runner's exits are market orders that the sandbox prices from a quote, so an exit that can't be priced is refused and retried on the runner's backoff (ADR 21), and the stale contract keeps being polled until it fills.
- **Recovery is reconciliation, at every step.** Before judging a run, the runner takes in any order whose outcome the run never recorded, whether the process died or the call raised. The sandbox tags every order with its run, so it can answer:
  - A pending leg whose entry the sandbox filled is held at that fill and watched, or closed if the run is stopping. An entry it never received fails the leg, and the order row becomes `not_sent`.
  - A closing leg whose exit the sandbox filled is closed at that fill, not at a later price. An exit it never received is sent again.
  - An order recorded without the sandbox's id is matched to the run's one sandbox order not yet matched. Orders go one at a time, so there is never more than one.
- **`recovery_failed` when the two disagree**: a recorded sandbox id the sandbox doesn't have. The run stops with that reason, and its legs are closed, capped as always at what the sandbox holds for them. The order row is marked `unreconciled` so it isn't looked at again. No fill price is ever made up.
- **On start**, the daemon notes on the timeline of every run not yet ended that it is watching it again. The ratchets were saved as they moved (ADR 21), so the run carries on from them, and nothing is entered again.
- **Every run records its trough**, the lowest P&L it reached, next to its peak.

## Consequences

- A strategy never decides on prices it hasn't seen. Losing the feed costs a poll every 2 seconds; losing quotes too stops the run within a minute.
- A daemon restart mid-run resumes watching with the ratchets it had, and a fill it didn't record is booked at its real price.
- The timeouts are set through the environment, for every strategy at once.
