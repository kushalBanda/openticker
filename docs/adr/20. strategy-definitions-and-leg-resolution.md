# 20. Strategy definitions and leg resolution

Status: Accepted

## Context

A rule-based options strategy ("sell the NIFTY ATM straddle on the weekly expiry") has to trade the right contracts on any day. Naming contracts in the definition would make it stale by the next expiry. Agents create and edit these definitions, so mistakes must be refused with a message that says what to fix, before anything runs.

## Decision

- **A definition names no contract.** Each leg (1 to 10) gives a side, a number of lots, CE, PE or FUT, an expiry relative to today, and for options a strike relative to at the money (or a fixed strike). Legs are named `leg1`, `leg2`, ... by position.
- **Expiries:** `weekly` is the nearest listed expiry (today's counts until 15:30), `next_week` the one after; both need weekly contracts, recognised by two listed expiries at most seven days apart, and are refused otherwise rather than silently meaning the monthly. `monthly` is the last expiry of the nearest month that has one, `next_month` the last of the month after. Futures take `monthly` or `next_month` only.
- **Strikes:** ATM is the listed strike nearest the underlying's spot price, ties to the lower strike (the same rule as the option chain, ADR 16). An offset counts listed strikes from ATM for the leg's own option type: `+2` is two strikes out of the money (above ATM for a call, below for a put), `-1` one in the money. Offsets go up to 20 strikes. A strike that is not listed is an error; it is never swapped for a neighbour.
- **Validation happens when the definition is built**, in the core types, and raises `InvalidStrategyError` with the reason: lots 1 to 50, times inside the 09:15 to 15:30 session, exit after entry, an intraday exit no later than the 15:15 square-off, a sold leg's percent target below 100, profit lock and limit rules from ADR 19. Creating a strategy also checks that its underlying is synced and has options.
- **Definitions are stored as versioned JSON** in a `strategies` table. Names are unique among strategies that are not deleted. Deleting marks the row, so orders a strategy placed keep naming it. Writes take the SQLite write lock first (`BEGIN IMMEDIATE`), so two processes can't claim the same name.
- **`update_strategy` replaces the whole definition.** `get_strategy` returns it in the same shape it is sent in, so an agent edits and sends it back.
- **`preview_strategy` resolves every leg at the live price and places nothing**, returning the contracts, their labels (ATM, OTM2, ITM1, FUT), quantities and last prices, and the net premium.
- **Only options strategies exist so far.** Alert-driven strategies add a second kind to the same table.

## Consequences

- The same definition picks different contracts from one day to the next, by design. A preview shows what it would pick right now.
- A thin or stale instrument master can make `weekly` look unavailable; `sync_instruments` fixes it.
- Strategies can be defined and previewed but not yet started.
