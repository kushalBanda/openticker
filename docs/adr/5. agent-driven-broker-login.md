# 5. Broker login as two agent tool calls, no callback server

Status: Accepted. Amended by ADR 33: `openticker-serve` also takes the broker's redirect itself, for a signed-in browser.

## Context

Broker OAuth (Kite Connect) redirects the browser to a registered URL carrying a one-time `request_token`. OpenTicker is usually operated by an agent over MCP stdio, with no web server running to receive that redirect.

## Decision

- `get_broker_login_url(broker)` returns the login URL. The human opens it and logs in on the broker's own page, then passes the `request_token` from the redirect URL back to the agent.
- `connect_broker(broker, request_token)` exchanges it for a session and stores it encrypted (ADR 3). It never returns the token to the caller.
- Adapters are built per call from the registry and read the stored session each time, so a reconnect takes effect immediately.

## Consequences

- No listener process running beside the stdio loop.
- Kite sessions expire daily; the agent sees a "reconnect" error and repeats the two calls.
