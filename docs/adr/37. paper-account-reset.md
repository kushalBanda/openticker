# 37. Resetting the paper account

Status: Accepted.

## Context

A paper account collects experiments: positions from a test that went wrong, a week of trades from a strategy since rewritten. A user who wants to start clean has had no way but deleting `~/.openticker`, which also loses strategies, scripts, keys and the audit log. A reset must not surprise anything still running: a strategy's runner or a hosted script can place an order at any moment, and one placed into a half-wiped account leaves positions and funds that disagree.

## Decision

- **A full wipe, nothing partial.** `reset_paper_account` deletes every sandbox order (pending ones too), trade and position, and the P&L recorded by day and by minute (ADR 34), and puts the funds back to the configured starting capital (`SANDBOX_STARTING_CAPITAL`) with nothing blocked, realized or charged. There is no funds-only reset and no numbered "epochs" of history: a strategy's ledger, built from its trades (ADR 29), starts again from zero.
- **What stays.** The audit log (it records the reset as `PaperAccountReset`, with how many orders, trades and open positions went), strategies and their runs, scripts, keys, the broker session and settings.
- **Refused while anything runs.** A strategy run not ended or a script run not ended refuses the reset (409), naming each. The check runs inside the same `fill_transaction()` as the wipe (`BEGIN IMMEDIATE`, ADR 11), so no run can start, and no fill can land, between the check and the wipe.
- **Confirmed twice, the web app's way.** The body must carry `confirm: "RESET"` exactly (422 otherwise). In Settings the button is a hold (1.2 s) that stays disabled until RESET is typed. There is no second sign-in (ADR 31).
- **Web only.** `POST /api/v1/account/reset` is not an MCP tool: an agent has no business wiping the account it reports on. A full-scope API key can still call it; script and review keys can't reach it (ADR 25, ADR 29).
- Settings shows the account's settings read-only (starting capital, capital cap, leverage) with where to change them: `.env`, then a restart.

## Consequences

- Starting over takes: stop what runs, type RESET, hold.
- Every page's figures change at once: the web app refetches everything on the reset's response, and other browsers on the event.
- Anything outside the sandbox tables that remembers an order id (a strategy run's orders, ADR 21) keeps pointing at orders that are gone; those runs have ended, so nothing reads them for trading.
