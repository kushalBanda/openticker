# 21. The strategy runner

Status: Accepted

## Context

A strategy defined and previewed (ADR 20) has to be entered, watched and closed with nobody in the conversation. Starting and stopping come from the MCP server and the REST API, which don't live as long as the daemon (ADR 12). Exits have to follow the per-leg rules (ADR 9) and the strategy-wide rules (ADR 19) on live prices. A mistake here either leaves a position unwatched or opens one nobody asked for.

## Decision

- **Control is a command, carried out by the daemon.** `start_strategy`, `stop_strategy`, `kill_strategy` and `close_strategy_leg` write a row to `strategy_commands` and return at once. The daemon's strategy loop carries each out within about a second and records what came of it: done, or refused with the reason. The checks a caller can act on (unknown strategy, already running, nothing to stop, unknown leg) are made when the command is written, so the tool fails there and then.
- **A start expires after 60 seconds.** One sent while the daemon wasn't running is refused when the daemon finds it, rather than entering at other prices hours later. Stops, kills and leg closes never expire.
- **The kill switch locks first.** `kill_strategy` sets the strategy's `locked` flag, cancels any start not yet carried out, and writes the kill, in one transaction; nothing can start the strategy until `release_kill_switch`, which is refused while the kill is still closing positions. `stop_strategy` also cancels a pending start.
- **A strategy is edited or deleted only while it isn't running** (openalgo's rule: a conflict, not a bad request). `update_strategy` and `delete_strategy` are refused while a run is open or a start is pending, checked inside the same write lock as the change. The limits a run is judged by are therefore the ones it started with.
- **Entry:** the market must be open, and an intraday strategy must be before the square-off. The legs are resolved as `preview_strategy` resolves them, the run is written with every leg pending, then each leg is entered with a MARKET order through the ordinary order path (`place_order`: validation, capital cap, market hours). Intraday strategies trade MIS, positional ones NRML. A leg's stop loss, target and trailing distance become prices measured from its own fill. If a leg can't be entered, the legs already entered are closed and the run ends with reason `error`.
- **Every strategy order is written to `strategy_orders` before it is sent** and updated with the sandbox's answer (ADR 14).
- **Watching:** every second, each open run is judged by `evaluate_strategy` (ADR 19) on the latest streamed price of each leg. Only a price received after the leg was entered counts. A leg whose own rule fires closes on its own and the run carries on; when a strategy-wide rule fires, the run stops and every leg closes. An intraday run stops at the square-off with reason `schedule`. A run whose legs have all closed on their own ends with reason `legs_closed`.
- **Ratchets are saved as they move** (trailed stops, best prices, peak P&L, the profit-lock floor, stops at entry), in the run's row, so a restarted daemon carries on from them.
- **Closing a leg by hand is an override, not a signal:** it never moves the other legs' stops to entry. A leg whose exit has been decided keeps counting towards the run's P&L, but its own rules are off, so it can't fire again while its exit is retried.
- **An exit never trades more than the sandbox holds** in the leg's direction. The square-off, an expiry settlement or a hand-placed order may have closed it already, and exiting blind would open a new position. A leg found already closed is marked closed with a note.
- **A failed exit is retried** after 30 seconds, then twice as long after each further failure, up to 10 minutes. Each failed attempt is an `OrderFailed` notification.
- **Per-run P&L comes from the run's own fills**, entry and exit price of each leg, never from the account's net position. The daily loss limit adds the realized P&L of the strategy's other runs started today.
- **Events:** `StrategyStarted`, `StrategyLegClosed` and `StrategyStopped` are audited and notified. Each run also keeps a timeline, in words a user reads, returned by `get_strategy_run`.

## Consequences

- An agent can start a strategy and end the conversation; `get_strategy_runs` and `get_strategy_run` show later what happened and why.
- Commands wait for `openticker-serve`; a start sent while it is down expires, and the tool's answer says the daemon carries it out.
- A leg with no streamed price holds up the strategy-wide rules (ADR 19). Illiquid contracts need the polling fallback and staleness rules of ADR 13, which the runner does not have yet.
- Two strategies trading the same contract share one net sandbox position; the exit cap above reads that net position, so it can close less than a leg holds if another strategy is opposite.
- Recovery of an order recorded but never answered, scheduled entries and exits, and closing on expiry day come with scheduling and durability (ADR 14).
