# 46. The desk manager holds things out for the day; it never unschedules them

Status: Accepted. Amends ADR 41 (lines are shown, not enforced) and ADR 44 (`contradicted`, and the plan's "doesn't run, so unschedule it").

## Context

The manager decides what runs each day, but the only tools it had for "doesn't run today" lasted much longer than a day. A line at capital 0 changed nothing on its own (ADR 41), so the skill had it also call `unschedule_strategy`, `unschedule_script` or `kill_strategy` in the same look. All three outlive the day, and nothing ever undid them:

- On 16 Oct 2026 the Kite session had expired before the plan wake, as it does most mornings. The plan, made without prices, unscheduled 13 strategies and all 7 alert scripts. `unschedule_script` deletes the schedule itself, wrote no audit entry and didn't touch `updated_at`, so nothing recorded what had been removed.
- Prices came back each day, but nothing put the schedules back. On 19 Oct the manager read the unscheduled scripts as "role isn't verified" and kept them off. On 21 Oct the user scaled five strategies up with ₹10L lines of their own, and those strategies were still unscheduled.
- On 22 Oct, again without prices, it killed 10 signal strategies, because `stop_strategy` doesn't stop a signal strategy listening for alerts. The kill switch holds until someone releases it.
- The signal strategies it marked "runs, listening" couldn't trade: their alerts come from hosted scripts that no longer ran. `undone` checked only stop lines and capital, so it listed nothing.

The desk made no trade from 20 to 23 Oct, and nothing on the desk said why.

## Decision

**A line at capital 0 holds its strategy or script out.** `held()` in `core/agents/manager.py` returns the strategy and script keys whose line is at capital 0, whoever set it, while the manager is on. The daemon and the alert URL honour that set:

- `start_scheduled` writes no scheduled start for a held options strategy;
- `accept_signal` records a held signal strategy's entries as `ignored` ("held out: its line on the Manager page gives it capital 0"). Exits still pass, so a position carried in can be closed;
- `start_scheduled_scripts` doesn't start a held script.

A hold closes nothing and changes no schedule. Give the line capital again and the strategy enters at its next due entry, or the script starts while its window is open. Turn the manager off and every hold lifts. The hold lasts as long as its line, not one calendar day: each plan and each close set the lines again, and when a line says the session is down after prices are back, the skill's duty 4 has it rewritten.

**Schedules are the user's.** A manager's key is refused `schedule_strategy`, `unschedule_strategy`, `schedule_script` and `unschedule_script` (`adapters/inbound/scopes.py`), and those tools aren't listed to it. It still starts and stops runs today, and may still kill, which the skill keeps for what it can't stop any other way.

**Schedule changes are audited.** `StrategyScheduleChanged` (with `previous_broker`) and `ScriptScheduleChanged` (with `previous`, e.g. "09:15-15:10 Mon,Tue,Wed,Thu,Fri NSE") are published by whoever schedules or unschedules, recorded with `triggered_by`. A schedule taken away can be seen on the Activity page and put back from the entry.

**Two more undone items (ADR 44):**

- **`starved`:** a signal strategy that trades today, whose alerts come from hosted scripts none of which will run today. A script will run if it is running now, or if its schedule starts it later today: today is one of its days, its stop time hasn't passed, no line holds it, and no run since today's start ended by itself. A script sends a strategy's alerts when its source holds that strategy's alert URL token. The token is matched by its hash, the same way the alert URL itself is matched. Alerts from TradingView or ChartInk can't be seen, so a strategy fed only by them is never listed. Listed whoever owns the line: starting the script works with the user's line, not around it.
- **`locked`:** a strategy the manager killed on an earlier trading day that is still locked, with no line holding it out. The fix is `release_kill_switch`, or capital 0 with a reason.

`contradicted` now means a held strategy with a run still open, so its only fix is `stop_strategy`. A held strategy that enters later or listens isn't listed: the hold already keeps it from trading.

## Consequences

- A blind morning costs one plan's lines, not the desk. When prices come back, the `restored` wake (or the next plan) gives capital back, and nothing is left to restore by hand.
- Capital is still not a size. Only capital 0 is acted on. A strategy trades its definition's size whatever capital its line gives it.
- A user's line at capital 0 holds too, while the manager is on. That is what the user said by setting it.
- Schedules removed before this change aren't in the audit log and have to be restored by hand.
- Finding feeder scripts reads each script's source on every `undone`. That is a handful of small files, read on every look and every `set_manager_numbers`.
