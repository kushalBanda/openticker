# 8. MCP tool design conventions

Status: Accepted

## Context

Agents are OpenTicker's primary users. An agent knows a tool only through what the server sends at `initialize` and `tools/list`: server instructions, tool name, title, description, input and output schemas, and annotations. Guidance followed: Anthropic's [Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents) and the [MCP tools specification](https://modelcontextprotocol.io/specification/2025-06-18/server/tools).

## Decision

Every tool in `adapters/inbound/mcp_server.py`:

- **Has a `title` and a docstring description** written for someone new to the domain: what it does, when to call it, what to call before or after it.
- **Declares `ToolAnnotations`**: `read_only_hint` and `open_world_hint` always; `destructive_hint` and `idempotent_hint` for every tool that writes. Writing to the local store counts as a write.
- **Describes every parameter** (`Annotated[..., Field(description=...)]`), uses enums (`Exchange`, `InstrumentType`, `Interval`) wherever the set of values is closed, and names parameters unambiguously (`start_date`, not `start`). Shared parameter types (`Broker`, `Symbol`, `ExchangeParam`) are defined once.
- **Returns a Pydantic model** from `mcp_models.py`, so the tool publishes an `outputSchema` and a `structuredContent` result. Fields carry descriptions where their meaning isn't obvious.
- **Keeps responses small by default.** Anything that can grow has a default limit the agent can raise (`max_bars`, `limit`), and a truncated response says so and says what to do (`note`, `truncated`).
- **Guides the next step** where the workflow continues (`next_step`).
- **Speaks exchange-local time.** Input dates are trading dates; returned times carry the `+05:30` offset. A daily candle reads `2026-09-18T00:00:00+05:30`, not `2026-09-17T18:30:00Z`.
- **Fails with actionable messages** (ADR 7).
- **Never returns secrets** (ADR 5).

The server sends `instructions` describing the overall workflow (connect, sync, search, then read) and the symbol format.

`tests/adapters/inbound/test_mcp_server.py::test_every_tool_is_fully_described_for_agents` enforces title, description, annotations, output schema, and parameter descriptions for every tool, including future ones.

`search_instruments` exists because an agent can't otherwise discover standardized symbols such as `NIFTY22SEP2623350CE` (ADR 4).

## Consequences

- Annotations are hints; clients must not rely on them for security.
- Tool names are not prefixed: MCP clients already namespace by server (`mcp__openticker__get_quote`).
- Any REST API should reuse `mcp_models.py`'s shapes, or map them one to one, so agent-facing and HTTP responses stay aligned.
