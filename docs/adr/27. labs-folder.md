# 27. The labs folder

Status: Accepted

## Context

Users operate OpenTicker from a coding agent: Claude Code, Codex, or another MCP client. The MCP server gives the agent tools, but nothing tells it how to do the research: how to turn an idea into a strategy, what to check before saving one, or where to write down what the strategy was for. Each session started from zero, and each user wrote their own instructions.

OpenAlgo ships skills for Claude Code inside its own repository (`.claude/skills/`), and users work in the cloned repo with a gitignored `workspace/` folder for their own files. It has no command that creates a workspace, and nothing for Codex. OpenTicker is also installed by cloning.

Two wrinkles decide the shape:
- Claude Code loads every `CLAUDE.md` from the directory it starts in and every parent directory. A trading session started inside the repository would load the contributor guidance in the root `CLAUDE.md`, which is about developing OpenTicker, not using it.
- The two agents look in different places. Claude Code reads `CLAUDE.md`, `.claude/skills/` and `.mcp.json`. Codex reads `AGENTS.md`, `.agents/skills/` and `.codex/config.toml`, the last only once the user trusts the folder.

## Decision

The repository ships a `labs/` folder. Users `cd labs` and open their agent there.

- **One set of instructions.** `AGENTS.md` holds them; `CLAUDE.md` is `@AGENTS.md`, so both agents read the same text.
- **One set of skills, placed twice.** Each skill sits in `.claude/skills/<name>/SKILL.md` and, identical, in `.agents/skills/<name>/SKILL.md`. Copies rather than symlinks, so they survive every checkout. A test fails if the two drift.
- **Both agents reach the same server**, `uv run --directory .. openticker-mcp`: in `.mcp.json` for Claude Code and `.codex/config.toml` for Codex. The agents start it from the folder they were opened in. From `labs/` that is the repository root; from a folder deeper inside `labs/`, uv walks up to the repository's `pyproject.toml` all the same, and the server finds the root `.env` from its own location, not the working directory.
- **Contributor guidance stays out.** Claude Code's `claudeMdExcludes` setting takes glob patterns matched against each file's absolute path. `labs/.claude/settings.json` uses it to skip every `CLAUDE.md` and `CLAUDE.local.md` above `labs/`. Files in a `.claude*` folder are kept, so the user's own global instructions still load. Codex reads `AGENTS.md` only from the repository root down, and the root has none.
- **The user's research is theirs.** `notes/` (one note per strategy: the idea, why it should work, what would prove it wrong) and `research/` are gitignored.
- **Skills arrive with the features that use them.** The first is `new-strategy`: from an idea in plain words, through questions that use the market's real numbers, to a saved strategy previewed against today's contracts and a note. It never starts or schedules anything unasked.
- **No MCP prompts or resources for this.** Skills do the same job in both agents, and users can edit them.
- `playbook/` explains the workflow to the user.

## Consequences

- A user gets a working research setup from the clone: `cd labs`, open Claude Code or Codex, describe an idea.
- Skills are text in the repository: users edit them, and a `git pull` updates them. A user who edits one merges on pull.
- Every skill change is made twice. The test catches a missed copy, not a bad edit.
- The exclude pattern also skips a `CLAUDE.md` the user keeps in a directory above their clone, unless it sits in a `.claude*` folder.
- If OpenTicker is ever installed from a package rather than cloned, `labs/` needs a command that writes it out. Nothing else here changes.
