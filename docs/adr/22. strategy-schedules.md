# 22. Strategy schedules

Status: Accepted

## Context

A strategy definition carries a schedule (ADR 20): an entry time, an exit time, the weekdays to trade and whether to close on expiry day. The runner (ADR 21) enters a strategy only on `start_strategy` and closes it only on its rules, the intraday square-off or a stop. A strategy that enters every morning, and closes at a set time or before its contracts expire, needs nobody to call a tool.

## Decision

We follow openalgo's scheduler, re-derived:

- **Scheduling is a separate switch.** An entry time alone never trades. `schedule_strategy` names the broker scheduled entries go through and arms them. `unschedule_strategy` disarms them and leaves an open run alone. It needs an entry time, and it is refused while the kill switch is on. The broker is stored on the strategy (`strategies.scheduled_broker`, nullable per ADR 18). A strategy can still be started by hand while it is scheduled.
- **An entry is due from its entry time for 60 seconds, on a scheduled weekday the exchange trades.** Holidays come from the market calendar (ADR 13). Each second the daemon writes a start command, triggered by `schedule`, for every scheduled strategy whose entry is due and which has no scheduled start at or after that time. The start is then carried out like any other (ADR 21). If it is refused (already running, kill switch, market closed), the refusal is recorded on the command, where `get_strategy_runs` shows it. An entry the daemon misses by more than 60 seconds, because it wasn't running, is skipped for the day. The start does not happen later at other prices.
- **Exit time closes a run on every trading day**, whether it was started by hand or by the schedule and whatever its horizon, once the run has been open across that time. A run started after the day's exit time carries on until the next trading day's. One missed while the daemon was down closes the run as soon as it next steps in a session. This is the safety half of the pair, so it does not depend on the switch. Reason `schedule`.
- **On the expiry day of any contract a run holds**, with `exit_on_expiry` (the default), the run closes at the exit time, or at the intraday square-off when there is none, instead of being settled at expiry. Reason `expiry`, which wins over `schedule` when both are due. With `exit_on_expiry` off, the position is left to expiry settlement (ADR 11).
- **A start its schedule would close at once is refused**, for example a strategy holding this week's contracts started on their expiry day after the square-off.
- The intraday square-off still closes every intraday run first (ADR 21).

## Consequences

- An agent can define a strategy, schedule it and leave. Every scheduled start the daemon sends is recorded as a command, with its outcome or the reason it was refused.
- The daemon has to be running at the entry time. If it is down for the whole 60-second window, that day's entry is skipped and nothing is recorded: no command was sent, and there is no run to attach a timeline entry to. `get_strategy_runs` then shows no start for that day.
- A positional strategy with an exit time is closed each day at that time, so it behaves like an intraday strategy held as NRML. To hold across days, leave the exit time out.
- The stop detail names the scheduled time; the timeline shows when the exit actually happened, which is later if the daemon was down.
