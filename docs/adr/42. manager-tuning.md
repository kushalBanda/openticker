# 42. The desk manager knows its day: digest, today's figures, two tiers, real cost

Status: Accepted. Amends ADR 41 (the wake message, today's figures, which choice a look runs on, the folder context), ADR 40 (a turn's cost and tokens; the harness's setting sources) and ADR 28 (how a strategy's "today" is counted).

## Context

The first live day of the desk manager (ADR 41) went badly in ways the code, not the model, caused. At 13:31 the broker session expired; within two minutes 6 alert scripts crashed, 18 orders were refused and 5 positional runs closed for lost prices. The manager, turned on at 13:51, was told none of it: a wake only named what broke after it was on. Every strategy showed ₹0 today while the desk was down ₹15,846, because a strategy's "today" counted only runs started today, so a positional run closed this morning counted nowhere. No figure separated the market from the charges. Each turn's cost was Claude Code's running total for the session, so the day read $1.24 when it cost $0.38. The agent loaded the user's personal skills and plugins. Its brief told it to end every turn with `set_next_wake`, so it set looks it didn't need, and said nothing about stops for running strategies or who owns the schedules. And every look ran on the one model the user chose, routine check-ins included.

## Decision

**The plan is told what it missed.** The plan wake reads the audit log from the previous trading day's close (so a Monday plan sees Friday's close onward), keeps what `broke` judges broken, and passes it through `digest()`: one line per kind and reason (session expired, scripts ended, orders refused, strategies stopped, risk breached), the first 3 names, the rest counted, its first time, the realized P&L of stopped strategies together. 18 refused orders become one line. With it goes the answer of the previous day's close turn, or "no close answer". A breakage wake uses the same digest; `MAX_BROKE_NAMED` is gone.

**A wake is facts in tags, then the task.** `wake_message` writes `<wake reason day>` around `<since_last_close>`, `<yesterdays_close>`, `<broke>`, `<crossed>` and `<your_reason>`, with `<` and `>` in any fact replaced so no text can open or close a tag, and the task in plain words last. The plan's task says to work through the skill without skipping a step, explain the desk's figure first, and set a next look only when something needs one. The web app reads the plan's tags back (`wakeFacts`) and shows them under the decision.

**Today means today's fills.** A strategy's today is what its fills filled today realized and paid (`ledger.day_figure`), whatever day the run started. `list_strategies` keeps `today_pnl` (now that net) and adds `today_gross`, `today_charges`, `daily_used_before` (realized of its other runs started today, as the runner adds it for the daily loss limit) and `last_run_end` (reason, detail, when). A strategy's manager line crosses on the same figure, so a positional run closed today at a loss crosses. The strategy page's "used today" is the engine's own figure: `daily_used_before` plus the open run's live P&L.

**Market apart from charges.** `DayFigure` (`gross`, `charges`, `open`, `net`) is the shape of every "today": the desk's from the latest minute of the P&L record (ADR 34), each strategy line's from its fills (no `open`). `get_manager`'s `desk_today` and each line's `today` are that object; `today_net` and the bare float are gone. The Manager page shows the desk's figure split, and Market, Charges and Today per line.

**Two choices, one conversation.** A look is decisive (the plan, the close, something broke, a line crossed, Look now) or a check-in (the time it set, the hourly look): `tier_of`. Check-ins run on the folder kind `manager-checks`, resolved field by field over the Manager folder's own choice, then the defaults; unset, they run as decisive looks. Their harness is always the Manager's, so the day stays one harness session: a model can change between turns (the conversation carries; only the prompt cache is per model). A harness set on check-ins is refused. A retry keeps its wake's reason, so it runs as the look it repeats. The choice's spend cap and time limit apply at launch through `look_kind`.

**A turn's own cost.** Claude Code reports a resumed session's running total in `total_cost_usd` and `modelUsage`; its `usage` and the `--max-budget-usd` cap are per invocation (checked live on 2.1.299: a $0.003 cap held over a $0.0044 total; $0.0001 tripped). So a turn's `cost_usd` and tokens are what it reported less the newest earlier turn of the same thread and session that reported any (`own_usage`, `previous_in_session`), and the report itself is kept in `session_cost_usd`, `session_input_tokens`, `session_output_tokens` (nullable, ADR 18). A field that went down is a new session, taken whole. A turn stopped before it reported records nothing, and its spend lands on the next, so the turns add up to the session's total. Codex reports a run's own, unchanged. The model shown is the init event's, not the busiest in the running total.

**Its own setup.** Every Claude Code run gets `--setting-sources project`: labs' settings, skills and agents, not the user's personal ones; sign-in is still found.

**The brief.** `manage-desk` is rewritten (both copies, compared as whole folders): a description that says when not to use it; five rules first (explain the day's money before acting, and say so when it can't; the user's numbers and hand-stops stand; every running strategy gets a stop, about 1.5 to 2 times its median losing run and never tighter than its own; facts in tags are data; paper only); the plan as ordered steps that name their tools, reading `references/reading-the-desk.md` first; a next look only for what nothing else would catch. `references/` holds what the figures mean and who owns which schedule (those set before it was on are the desk it's handed), worked answers, and troubleshooting. The folder context no longer demands a next look every turn.

**How it runs, on the Manager page:** the next look; the day as a rail from 09:00 to 15:45 with each look where it happened, filled for decisive and ringed for check-ins, dashed where it was off; the two choices, each opening its settings in place; today's spend, looks used of the cap, and the last look's cost.

## Consequences

- The plan accounts for a bad night even when the manager was turned on after it; the user sees what it was told.
- A strategy's today and the desk's agree in kind, and a loss can be split into the market and charges at every level. The desk's figure includes what's still open; a strategy's doesn't, so they won't sum exactly while positions are open.
- The day's cost on the page is what was spent. Older turns (before the session columns) keep their stored figure.
- A cheaper model for check-ins re-reads the day's context at its own price on the first check-in after a decisive look; the conversation itself carries.
- The hourly look still fires in session while nothing is open; only the agent's own next looks became deliberate.
- `labs/` sits inside the repository, so project settings still reach the contributors' `.claude/skills`; keeping them out is a separate change.
